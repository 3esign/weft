Numeric kernel: `core/weft_geom.js` (+ `_ext`, `_ext2`, `_ext3`, `_ext4`): exact twins of the numpy/scipy/skimage
and CPython pieces the scripts use — pairwise summation, glibc `hypot` vs CPython `math.hypot`, half-even rounding
with `-0.0`, Felzenszwalb EDT with scipy semantics, scipy labelling order, skimage `find_contours` incl. its deque
assembly, cKDTree k-NN, OpenBLAS FMA in 2-vector dot, `json.dumps` float repr. Measured residual risk: V8's
`sin/cos/atan2/pow` differ from glibc in the last bit for 3–14 % of calls; perturbing them by one ulp in the tests
left every output byte-identical (one `0.0`→`-0.0` token in OBLAK when *every* call is perturbed).

### The chain runs without Python

`weft.mjs`: `build <model>` now runs the JavaScript generator by default (`--python` runs the original); flags are
identical. Verified end to end: `node weft.mjs build climber --machine a2l --H 240 --legs 3 --allow-experimental-membrane`
→ geometry → thread → gate PASS → header → `.gcode.3mf` → package re-gated, G-code sha256 a88694f5… (the P2b that printed).

Two pre-existing defects in `weft.mjs` fixed on the way (both reproduced first): the belief/measurement step read
cap centres as `cx/cy` only, so the death caps of climber/vase/paired/aero (`c:[x,y]`, no `anchoredFrac`) were
refused as "undeclared" — `build climber` through `weft.mjs` could never succeed; and the climber strategy centres
the geometry's bounding box on the plate, which the step did not know — `core/weft_build.mjs` now reports
`placement:{ox,oy,bbox}` and the step uses it. A declared cap without a belief is now reported as such and only a
membrane with no cap record within 3 mm is undeclared.

### Machine-profile wizard (new)

`core/weft_machine_wizard.mjs`: any file sliced by Bambu Studio, OrcaSlicer, PrusaSlicer or Cura (or an unknown
plain G-code) → a `machines.json` entry candidate with the start/end blocks cut by the same rule the harvested A2L
blocks follow, every value with its source key, the bead always `ASSUMED` (a slicer line width is not a measured
bead), and a `needsReview` list. `node core/weft_machine_wizard.mjs FILE --id NAME --out DIR` writes the three files;
it never touches `machines.json`. On the printed LIMIT16 package it recovers nozzle 0.4, layer 0.24, plate 330×320,
220/55 °C, and a start block equal to the 2026-09-02 harvest (the only diff is WEFT's own four comment lines).
`tests/machine_wizard.test.mjs`: 18 checks. Prusa/Cura/Orca fixtures are synthetic; real exports are wanted.

printed" statement is a byte comparison with the files that printed, not a new print. The Windows checkout was not
re-run; the PC's Python (Inkscape's, no scipy) will now skip the parity tests and run the JS generators.
