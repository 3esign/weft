# WEFT compiler audit · 2026-09-02 · "no path may float"

Triggered by **WEFT-01**: P2 Penjač was delivered with five filled discs hanging in mid-air. Semir found them in
the slicer. The rule he stated, and which this document exists to enforce: *floating must not even be able to appear.*

An independent audit of `climber_geometry.py`, `make_climber.mjs`, `suma_geometry.py`, `make_suma.mjs` follows.
Findings are the auditor's; the disposition column is the builder's plan.

## The root

**F1 — nothing refuses output.** Every check in the pipeline is a field in a JSON report.
`supportCheck.violations`, `tipCrowding.violations` and `caps.maxSpan_mm` are computed and then `json.dump` runs
unconditionally; the builders echo the report and go on to write the STL and the G-code without ever reading it.
There is no `sys.exit`, no `throw`, anywhere. Every other finding below is only dangerous because of this one.

## Findings that put material in the air

| # | where | what slips through |
|---|---|---|
| F2 | `climber_geometry.py` support check | The "bridge" branch is never really evaluated: it tests `maxStep`, which is the **perpendicular offset of the worst point from the nearest support**, not a span, and it never checks that the run has supported ends. An 11 mm offset is a cantilever — strictly worse than an 11 mm bridge — and is filed as legal. `suma_geometry.py` has no bridge concept at all. |
| F3 | cap threshold, both | A hole is capped when `r_ins < w/2 + e + ρ + 1.5`, so the largest admitted membrane span is `w + 2e + 2·bead + 3.6`, with **no term referring to maxBridge**. suma defaults give 11.5 mm against a limit of 12; `--w 6` gives 12.5, over. climber on a thick-wall layer gives 14.9 vs 12. `maxSpan_mm` is reported and compared to nothing. |
| F8 | `climber` death closure | `if (nxt[cm]>0).any(): continue` — a **single overlapping pixel** means "it continues upward", so no cap; `contours_of` then discards any contour under 2 mm². A limb that leaves a 1.5 mm² sliver above gets no cap and no wall: open tube, no event, no entry anywhere. Same mechanism as WEFT-01, one level up. |
| F9 | both, layer bookkeeping | For a contour-less layer `cur_pts=None` and `prev_pts` is set to it unconditionally, so **the next layer is never support-checked** and never enters `shifts` — while the summary reports as if every layer were covered. `make_climber.mjs` additionally drops a layer's caps together with its contours, losing legitimate closures. |
| F13 | `climber` arms | Arms survive the morphological opening by 0.28 mm of arithmetic coincidence (`0.7 − bead`), from two unrelated literals. `--bead 0.8` erases every arm from the mask while `ARMS`, `phase_at` and `wall_w` keep being driven by the nominal table. `core_r` is explicitly clamped against exactly this; the arm radii are not. |
| F14 | foundations, both | Brims are built from **nominal** part radii and never compared with the layer-0 mask they must support. suma uses a fillet radius on layer 0 used on no other layer, so layer 0 and layer 1 disagree about what is connected. |
| F15 | both | `onFoundation: True` is asserted, never tested — it can never be `False`, so a first-layer component sitting off the brim can never be caught. |

## Findings that silently change the object

| # | where | what slips through |
|---|---|---|
| F4 | `climber.parts_at` | A phantom `+0.01` disc is appended alongside the full core through the hips. It changes the raster by nothing, but `wall_w` takes `min(radius)` over the parts, so `w` is pinned to its 2.6 mm floor for ~48 layers **exactly where the legs merge — the heaviest load path** — and `RHO_at` drops 1.7 mm in one layer at the band edge. ## Disposition — in this order

1. **The gate.** `check_gcode.py`: validate the FINAL G-code, because that is the only artifact actually printed.
   Rasterise each layer's extrusions at bead width; every extruding point of layer *k* must lie within
   `bead/2 + allowance` of layer *k−1*'s material, or belong to a run of unsupported points that is bounded by
   supported points at **both** ends and shorter than maxBridge. A run with a free end, a run over maxBridge, or a
   whole path with no supported point at all — **FLOATING** — fails the build. Fixes F1, and makes F2, F3, F8,
   F9, F13, F14, F15 detectable no matter which of them is the cause.
2. **Refuse.** The geometry scripts exit non-zero on any violation; the builders run the gate before writing and
   delete the output if it fails. Nothing ships that has not passed.
3. **Regression fixture.** The known-bad P2 G-code (the one with five floating discs) is kept. The gate must fail
   on it. A checker that cannot reproduce the bug it was written for is not evidence.
4. Then the design-level findings, in severity order: F4, F5, F13, F8, F9, F3, F6, F7, F11, F12, F10, F17.

## WEFT-02 — the weave itself, found while building the gate (2026-09-02, same day)

The gate was written to catch WEFT-01. On the known-bad P2 G-code it reported the four floating hand
caps as intended — and 285 more problems nobody had asked about. They were not a threshold artefact.

**What was wrong.** `webLayer`, branch `staple`, sized the rung half-step `D` **once**, from
`curvAt(cl, cl.total/2)` — the curvature at the *middle* of the contour — and then tested every rung
against its **own local** curvature with `rungTooTight`. On any contour that is not a perfect circle the
test failed wherever the curve is tighter than its midpoint, and the rung was dropped with a bare
`continue`. Measured on P2 Penjač: **38 % of all rungs dropped; on half of all web layers every single
rung was dropped**, so the thread ran on ONE rail for the whole turn — a woven layer with no welds in it
— and the chord rail above hung in the air for up to **65 mm** against a 12 mm limit.

It is the WEFT-01 fault exactly: **one global number deciding a local question.** WEFT-01 was a global ρ;
this was a global curvature. Both were invisible because nothing measured the emitted result.

**Why it never showed on the prints that worked.** D5 (R140), Šuma and Parasol are large-radius bodies:
mid-contour curvature ≈ local curvature, so almost nothing was dropped. The fault needs a small, tightly
curved contour — a 10 mm leg — to bite. The compiler was not broken; it had a blind spot, and the
climber walked straight into it.

**Fixed.**
* `D` is solved where the rung actually lands, not at the midpoint.
* A rung that will not fit **gives up its overhang tab first** (reach shrinks toward w/2 in five steps).
  The tab is decoration; the rung is structure. Only a corner that cannot carry a crossing at zero tab
  is skipped — and the skip is counted.
* `perp` got the same treatment, and its tab is now *ramped* along the run instead of stepped, which
  removed 96 of its 105 unintended overlaps on a R45 dome.
* `webLayer._skipped` and `webLayer._maxRail` are published, stamped onto the layer, and **read**:
  `validityReport` now derives `maxChordSpan_mm` from the arc the web actually left unwelded instead of
  from the parameter `P.lambda/2`, and raises an error — not a warning — when it exceeds maxBridge or
  when any web layer placed no crossing at all.

**Regression evidence (old app vs new, same parameters):**

| case | weld nodes | thread | overlaps | chord span reported | valid |
|---|---|---|---|---|---|
| D5 dome R140 — *the one that printed* | 5760 → 5760 | 124095 → 124095 | 0 → 0 | 9 → 9 | true → true |
| D5 dome R75 λ18 | 5760 → 5760 | 124095 → 124095 | 0 → 0 | 9 → 9 | true → true |
| dome R20 tight staple | 19344 → 19344 | 183205 → 183207 | 0 → 0 | 3 → 3 | true → true |

`npm test`: **53/56 before, 53/56 after, the same three pre-existing preset failures.** Nothing that
printed changed; what changed is that the layers which were quietly unwoven are now either woven or
refused.

## WEFT-03 — the same fault one level down, in the node field

Rebuilding the climber on three legs surfaced the third instance. `Dcap` — the ceiling on the staple
half-step — was `0.45 × half`, where `half` is the **minimum** node gap anywhere on the contour. One
tight pair of columns therefore shrank every staple on the whole ring, and the rungs that no longer fit
were skipped: 143 of them, leaving a 19.3 mm unwelded rail. Global number, local question, third time.

The fix is a negotiation rather than a clamp. A staple's half-step can never exceed 0.45 of the gap to
the *next* column, and on the inside of a corner the legs converge by (1 − reach·k). Together they give
a closed-form ceiling on the wall at every column:

    0.45 · gap_i · (1 − reach·k_i) ≥ bead      ⟹      reach ≤ (1 − bead/(0.45·gap_i)) / k_i

The tightest column sets the layer. When a band asks for a wall its corners cannot turn, the geometry
now **halves the weld columns dyadically** (so the survivors stay registered) until the wall fits, and
stops halving at maxBridge. Fewer, longer runs where the wall is thick — which is what a thick band
wanted anyway. Only if that is still not enough do the wall and tab scale down together.
