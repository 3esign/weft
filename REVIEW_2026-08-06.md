# WEFT — independent review, verification and revision · 2026-08-06

This is the honest report requested for the current state of the project.
Method: I read every file in the repo, re-ran the claimed geometric
invariants as real headless tests against the live app, validated the
shipped E1 specimen STL numerically, fact-checked the hardware claims and
all eight paper references on the web, then fixed what could be fixed
without touching the geometry of the pending experiment. Everything below
is measured, not assumed; the test suite that produced these numbers is now
committed (`npm test`, 30 checks, all passing as of this revision).

## The headline

The core of this project is real and holds up under adversarial checking.
The geometry engine does what PROJECT_STATE.md and the paper draft say it
does, to the digit: dome apex angles sit on the base angular grid to
8.9e-16 rad, width-wave zeros land on node positions to 7.9e-14 mm, the 90°
miter is hw·√2 to nine decimals, the staple's hairpin offset is 0.5175 mm at
bead 0.45 exactly as documented, and the loop stitch produces exactly 4
self-crossings and 19 chord-crossing welds per 40 mm — the same figures the
paper reports. Most convincingly: the shipped E1 plate STL regenerates from
the app bit-for-bit — 269,520 triangles, identical bounding box, coordinate
checksum agreeing to 5e-7 over a 1.7e7 sum. The artifact in `specimens/` is
exactly what the code produces, which is the reproducibility standard most
research software never meets. The vendored three.min.js is byte-identical
to npm `three@0.128.0` (sha256 match), so the offline story is clean too.

The weak spots were concentrated in one place: the G-code emitter — the
part of the pipeline that has never been physically exercised (nothing has
been printed yet). It had four genuine printing-relevant bugs, all now
fixed and regression-tested. A fifth defect (inside-out STL facets) sat in
the STL path but was masked by slicers' silent auto-repair.

## What was broken, and is now fixed

First-layer speed was keyed on array index instead of height. In batch
mode, layers are z-sorted across all 16 specimens, so only one specimen got
the 15 mm/s first layer; the other fifteen printed their bed layer at 18
mm/s (via an also-misapplied bridge rule). On a plate whose entire purpose
is comparable specimens, 1 of 16 would have had different bed adhesion
conditions. Now keyed on z=0; the suite asserts every first-layer move in
the E1 G-code is ≤15 mm/s.

The emitter never touched the part-cooling fan. A Route B print would have
run the whole PLA lattice — bridges, tabs and all — with whatever fan state
the harvested header left, typically off. That alone could have sunk the
Route A vs Route B comparison and been misread as a flow-boost effect.
There is now a fan parameter (default 100%), M106 after layer one, M106 S0
in the footer.

Travels between specimens were unretracted, unhopped 38 mm drags at lattice
height. The E1 G-code contains 1,071 of them, one per specimen change per
z-level, each dragging a wet nozzle across up to three fresh thin-wall
lattices. Now: retract 0.8 mm + z-hop 0.4 mm between specimens — and
deliberately never within an object, because single-thread continuity is
the method. The suite counts the 1,071 retract/unretract pairs.

Extrusion volume used a rectangular bead cross-section, about 13% more
material than the stadium model every slicer (including Arachne on Route A)
uses. Since Route A vs Route B agreement is the project's own end-to-end
check, and the point of Route B is to isolate node flow boost, a 13%
baseline over-extrusion would have contaminated exactly that comparison.
Now stadium: (w−h)·h + π(h/2)². This is the right moment for the change —
nothing has been printed, so no calibration is invalidated.

STL facets were wound inside-out. The scene is y-up, the file is z-up, and
that axis swap mirrors chirality; the exporter never compensated. Measured
on the shipped plate: total signed volume −7413 mm³, 909 of 1007 shells
negative. Slicers auto-repair this silently, which is why Route A pilots
worked anyway — but the stored normals also disagreed with the winding, and
correctness shouldn't lean on repair heuristics. The exporter now reverses
winding and writes matching normals (suite-checked: positive volume, 100%
normal/winding agreement on sampled facets). The shipped E1 STL was rewound
in place with the same fix — identical coordinates and triangle count,
fiducial preserved, volume now +7413 mm³.

Smaller items, same standard: the jitter seed now resets on every build in
all modes (previously batch-only, so a manifest's `jitter_seed` could not
actually reproduce a wall or dome — contradicting the paper's
reproducibility claim); the overlap checker now reads each layer's stamped
overshoot rather than the possibly-restored live parameter; the app no
longer opens showing only layer 0 of the model (it opens on the full
build); the bed-fit check now uses the A2L's real 330×320 plate instead of
330×330; the layer bar shows each layer's stamped web type instead of the
current selector; and a missing vendor/three.min.js now fails with a
message instead of a silent hang.

## What was overclaimed, and is now corrected in the docs

Three documentation claims did not survive checking. First, PROJECT_STATE
called the A2L "CoreXY-class"; it is a bed-slinger (A1-style Cartesian,
moving bed) — the rest of the hardware facts (330×320×325 mm, open frame,
300°C/80°C, four nozzle sizes, June 2026 launch) all verified against
Bambu's official pages. Second, the safety modal and README instructed
"File → Import → Import Sliced File" in Bambu Studio; that menu path does
not exist for G-code — external .gcode is previewed by dragging it onto the
Preview tab. For a workflow whose safety story is "you preview before you
print," the instruction has to be executable as written; it now is. Third,
the paper's fillet claim ("worst interior turn 35°") holds only without
width modulation: measured 28.1° at amp=0 (all current experiments), but up
to ~72° at amp=2, because uniform-t bezier sampling concentrates curvature
mid-fillet at very sharp corners. The claim is now scoped in
PROJECT_STATE, recorded as a known limit in the suite (T6b), and flagged
for the draft. Also cosmetic but recorded: width-wave zeros measure 7.9e-14,
so the paper should say <10⁻¹² rather than <10⁻¹⁴, and the "603→102 points"
simplification figure is actually 602→102.

One finding that looked like a bug but isn't: the default S-arc preset
shows ~203 overlap warnings. Those are real — on tightly curved plans the
staple hairpin legs, defined in parameter space, compress below bead
clearance on the inner flange. The checker is doing its job; straight
walls and the whole E1 plate report zero. The proper fix
(curvature-scaled hairpin offset) is documented in §10 of PROJECT_STATE as
deferred, for the same reason the fillet fix is deferred: both change
emitted geometry, and the E1 plate's bit-reproducibility is frozen until it
is printed. That freeze is now a stated convention with teeth — the suite
embeds the plate's checksum and will fail loudly if geometry drifts.

## The paper

The draft is honestly framed (it explicitly makes no mechanical claims
ahead of prints) and its software-verification section matches what I
measured, with the two scoping corrections above. All eight references
checked out or now have real selections: five were essentially correct with
details fixed (Arachne is 2020, not 2020/2022; Mesh Mould's citable paper
is Hack & Lauer 2014 — Gramazio and Kohler are the lab, not the authors;
FullControl is single-author; CrossFill's venue is Computer-Aided Design
114), Branch Technology's citable source is the 2020 patent (no
peer-reviewed paper exists), and the two placeholder slots now have
concrete candidates: Gosselin et al. 2016 for curvilinear 3DCP toolpaths
and Maskery et al. 2016 for band-localized failure in graded lattices. One
honesty caveat matters: no well-cited paper literally demonstrates
"sinusoidal curvature braces fresh concrete beads against buckling" — the
draft should soften that sentence or pair Gosselin with Suiker et al. 2020
(which covers the buckling mechanics, on straight walls). Full paste-ready
citations with DOIs are in `paper/references_verified.md`.

## What I deliberately did not touch

The five deferred items in PROJECT_STATE §10 remain deferred, as
instructed. The web grammars, registration, LOD/grading and all synthesized
geometry are untouched — verified by the plate checksum. The paper's prose
remains yours; corrections are delivered as a companion file, not silent
edits. The E1 manifest is untouched. The 13.5 MB STL stays in git (fine at
this scale; consider git-lfs if specimens multiply).

## Where the project actually stands

Software: ready, and now verifiably so. Experiment 1: generated, validated,
not printed — every mechanical question in the paper is still open, and
the honest status remains "no physical results." The decision tree
(perp survives → welds are joints; only diagonals survive → welds are
hinges) is well-designed and everything downstream is correctly sequenced
behind it. The one thing this review could not do is the one thing the
project has been building toward: put the plate on the A2L. The path
there is unchanged and is written in PRINT_INSTRUCTIONS.md — calibrate the
single-line width first (bead 0.45 is a placeholder), Route A first,
photograph before touching, fill the manifest, rename the folder. Route B
is now materially safer than it was yesterday: first layers slow, fan on,
no drag-throughs, slicer-consistent flow.
